## 一、规范清单

### 1. 架构与分层规范
- 六层单向依赖：`core → engine/workspace/output → service → cli`（见 `ARCHITECTURE.md` §1）。
- `engine` 不得依赖 `service`/`cli`——保证"引擎=库、壳=服务"双形态可用。
- 根目录禁止散落脚本。
- **强制手段**：`scripts/check_structure.py`（分层反向依赖直接失败）。

### 2. 枚举与数据契约规范
- **枚举单源**：所有取值只在 `core/enums.py` 定义，禁止硬编码字面量。
- **契约单源**：字段名/编号算法/八要素只在 `core/contracts.py` 声明。
- 契约只增不破，升版规则见 `P1-3_契约升版策略.md`。
- **强制手段**：`check_enums.py` + `tests/test_contract.py`。

### 3. 代码质量规范
| 维度 | 工具 | 阈值 |
|---|---|---|
| 风格 / 导入排序 | ruff | `line-length=100`，规则集 E/F/I/W/B/C4/UP/SIM/RUF/PLR/BLE/C90 |
| 圈复杂度 | ruff(mccabe) | **单函数 ≤ 10** |
| 类型 | mypy | 新增代码必须通过（无豁免） |
| 安全 | bandit | MEDIUM 及以上零告警 |
| 测试 | pytest + coverage | 覆盖率门槛分阶段抬升（5 → 30 → 50） |
| 密钥 | check_secrets | 零命中 |

### 4. 安全与入库规范
- 密钥只在 `.env`；只提交 `.env.example`。
- 被测代码**只读**：分析后置只读，且**实测**可写性（`workspace/readonly.py`）。
- 目标目录逃逸到祖先仓库 → 阻断（`engine/diff_tag.py`）。
- 服务不返回堆栈；日志遮蔽 password/token/secret/authorization 等字段。
- LLM 通道做 **Prompt 注入防护** + **防幻觉校验层**（接口必须真实存在）。

### 5. 协作与流程规范
- 提交信息：`type(scope): subject`（Conventional Commits），`check_commit_msg.py` 强制。
- type ∈ `feat|fix|refactor|docs|test|chore|perf|build|ci|style`。
- 分支：功能分支命名 `feat/*`、`fix/*`、`docs/*`。
- 提交前钩子：`sh scripts/install_hooks.sh`（按项目分派，谁有改动跑谁的门禁）。

### 6. 服务化与部署规范
- 版本化 API 前缀 `/api/v1`；`/health` 与 `/ready` 分离。
- 错误结构统一 `{code, message, detail?}`。
- 结构化 JSON 日志，携带 `request_id`。
- **已知债务**：端点当前同步执行，异步化 + webhook 属服务化改造阶段。

## 二、通俗说明（给非技术人员）

- **分层规范** = 房子里的"水管不能往回接"。高层可以调用低层，低层不能反过来。
- **枚举单源** = 全公司只用一本"术语字典"，避免同一个词在不同表里写法不一样。
- **契约单源** = 出厂的箱子必须贴同一张标签，谁看都认得。
- **八环门禁** = 出厂前的八道质检，任何一道不过就退回去重做。
- **只读工作区** = 借用别人的书，看完就锁进柜子，防止被误改。
- **防幻觉校验** = 不允许模型"编"出代码里不存在的接口；编了直接丢。
- **黄金样本** = 一把标准尺，新旧系统量同一个东西，看谁量得准。

## 三、不足与改进方向

| # | 不足 | 影响 | 改进 |
|---|---|---|---|
| 1 | 端点同步执行 | 大仓库请求耗时 | 异步任务化 + webhook 回调 |
| 2 | 覆盖率门槛尚低（5%） | 测试保护不足 | 随 P3/P4 抬到 30% / 50% |
| 3 | 前端路由用正则提取 | 复杂写法漏提 | 引入 Tree-sitter / 前端 AST |
| 4 | 门禁配置与 legacy 双份 | 存在分叉风险 | 自动哈希比对（升版策略防线 3） |
| 5 | Windows 目录只读不硬 | 目录仍可写 | 生产走容器 `:ro` + 非 root |

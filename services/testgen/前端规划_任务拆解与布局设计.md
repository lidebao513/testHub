# testgen-service 前端规划：任务拆解与布局交互设计

> 配套交付：`service/web/demo.html`（可预览的交互原型）。
> 现状锚点：后端已具备 24 个受 `require_auth` 保护的端点（生成 / 执行 / 报告 / 追溯 / 覆盖率 / 智能输入 / 对比 / 流水线 webhook / 指标）；当前 `service/web/` 仅有占位 `index.html`，**无真实前端**。本规划基于真实端点反推前端需求。

---

## 一、技术栈建议

| 维度 | 选型 | 理由 |
|---|---|---|
| 框架 | **Vue 3 + Vite + TypeScript** | 与 testhub 前端栈一致，降低后续对接成本 |
| UI 库 | **Element Plus** | 表格/抽屉/步骤条/表单开箱即用，暗色主题完善 |
| 状态 | **Pinia** | 全局：当前项目、AUTH_TOKEN、异步任务轮询池 |
| 路由 | **Vue Router** | 页面级路由，侧边导航驱动 |
| 请求 | **Axios 封装** | 统一注入 `Authorization: Bearer <AUTH_TOKEN>`、loading、401 跳转 |
| 国际化 | **vue-i18n** | 中/英双语（testhub 要求 i18n） |
| 图表 | **ECharts**（按需） | 覆盖率、运行状态趋势、scope 分布 |
| 文档渲染 | **markdown-it** | 报告 md 渲染 |

## 二、前端任务拆解（颗粒度细化）

### P0 · 基础框架（地基，必须先做）
- **P0-1** 脚手架：Vite + Vue3 + TS + Element Plus + Pinia + Router + vue-i18n + Axios 初始化
- **P0-2** 布局外壳：可折叠左侧导航 + 顶部全局栏（项目选择器 / 鉴权 Token 入口 / 语言切换）+ 主内容区
- **P0-3** 鉴权层：`AUTH_TOKEN` 输入/存储（localStorage 加密提示）/ 请求头注入 / 401 统一处理 / Token 失效引导
- **P0-4** API Client：对照 24 个端点生成 TS 接口定义与请求封装（含错误码、loading 态、超时）
- **P0-5** 暗色主题：对齐 IDE dark 规范（背景/卡片/图表文字对比度），变量集中管理
- **P0-6** 通用组件：分页表格封装、筛选栏、详情抽屉、状态徽章（NORMAL/ABNORMAL/AUTH/PRIV_ESC/BOUNDARY）、空态/加载态

### P1 · 核心数据视图（演示必需）
- **P1-1** 项目列表页：GET `/projects`，卡片/表格展示，支持切换当前项目（Pinia）
- **P1-2** 项目概览仪表盘：统计卡（功能点数 / 用例数 / 覆盖率 / 上次执行状态）+ scope 分布饼图 + 最近运行趋势
- **P1-3** 测试点列表页：GET `/projects/{pid}/test-points`，表格 + **scope 筛选（正常/异常/安全/边界）** + 关键词搜索 + 点击行弹出详情抽屉（含语义键/追溯键）
- **P1-4** 用例列表页：GET `/projects/{pid}/cases`，八要素展示（前置/步骤/期望/类型/标签/优先级/追溯键/范围），支持按 scope 与 tag 筛选
- **P1-5** 执行任务页：GET `/tasks`、`/tasks/{id}`，任务列表 + **轮询状态**（pending/running/done/failed）+ 进度条 + 结果摘要

### P2 · 生成 / 分析流程（核心差异化能力）
- **P2-1** 智能输入对话框（A1）：单输入框混合接收「仓库地址 + 目标 URL + 账号密码」，调用 `/parse-input` 解析预览（脱敏展示），POST `/dialogue/submit`
- **P2-2** 生成流水线页：`/analyze` → `/generate`（默认 `execute=false`）→ 可选 `/execute` 的步骤可视化（Stepper + 每步进度/产出计数）
- **P2-3** 代码拉取页：`/pull` 展示取码/加深状态、增量基线校验结果
- **P2-4** 对比页：`/compare` 全量 vs 更新 diff（新增/变更/废弃测试点高亮）

### P3 · 执行与报告（闭环价值）
- **P3-1** 运行记录页：GET `/projects/{pid}/runs`（批次列表）→ `/runs/{batch_id}`（每用例结果 / **截图** / 耗时 / 判定维度）
- **P3-2** 报告页：GET `/report` 渲染 md/html，导出 **pdf/docx/xlsx** 下拉按钮（对应 `REPORT_FORMATS`）
- **P3-3** 覆盖率页：GET `/coverage`，按模块/维度统计 + 缺口可视化
- **P3-4** 追溯体检页：GET `/traceability`，孤儿检测（应为 0）+ 功能点→用例链路图

### P4 · 集成与运维（服务化定位）
- **P4-1** 流水线门禁页：`/verify/webhook` 触发配置 + 发布事件→结果回传（success/failed/blocked）可视化
- **P4-2** 监控页：GET `/metrics`（Prometheus）面板化展示
- **P4-3** 工作区状态页：GET `/workspaces`（只读代码目录 / 输出区 / 端口占用）
- **P4-4** i18n 双语补全（中/英）
- **P4-5** 响应式 + 移动视口（G-7 移动端执行结果的回看适配）

## 三、界面布局规划

### 整体骨架
```
┌──────────────────────────────────────────────────────────┐
│  顶栏: [Logo] [项目选择器 ▾]        [Token ◉] [语言🌐] [用户] │
├──────────┬───────────────────────────────────────────────┤
│ 侧边导航 │  主内容区（按路由切换）                         │
│ (可折叠) │                                               │
│          │  ┌─ 页头(标题+操作按钮) ─┐                     │
│ 总览      │  ├─ 统计卡 ×4 ──────────┤                     │
│  ├ 仪表盘 │  ├─ 图表区 ─────────────┤                     │
│ 资产      │  └─ 表格/列表 ──────────┘                     │
│  ├ 测试点 │                                               │
│  ├ 用例   │  详情抽屉 →（从右侧滑出，显示八要素/链路）      │
│  ├ 覆盖率 │                                               │
│  ├ 追溯   │                                               │
│ 流水线    │                                               │
│  ├ 智能输入│                                               │
│  ├ 生成   │                                               │
│  ├ 执行   │                                               │
│  ├ 对比   │                                               │
│ 执行记录  │                                               │
│ 报告      │                                               │
│ 集成      │                                               │
│  ├ 门禁   │                                               │
│  ├ 指标   │                                               │
│  └ 工作区 │                                               │
└──────────┴───────────────────────────────────────────────┘
```

### 导航分组逻辑
- **总览**：仪表盘（一眼看全局健康度）
- **资产**：测试点 · 用例 · 覆盖率 · 追溯（被测对象的"产物资产"）
- **流水线**：智能输入 · 生成 · 执行 · 对比（"生产"动作）
- **执行记录 / 报告**：运行批次与交付物
- **集成**：门禁 · 指标 · 工作区（服务化/运维视角）

### 关键交互约定
1. **列表页统一范式**：顶部筛选栏（scope 多选 + 关键词 + 标签）+ 下方分页表格 + 行点击→右侧详情抽屉（不跳页，保留列表上下文）。
2. **长任务范式**：提交后进入轮询（前端 `setInterval` 调 `/tasks/{id}`），进度条 + 状态徽章；完成后自动刷新列表并 toast 通知。
3. **scope 筛选**：测试点/用例页默认四色标签（正常/异常/安全/边界），支持多选过滤——这是本项目核心切分维度，前置展示。
4. **报告导出**：报告页右上角下拉菜单（md / html / pdf / docx / xlsx），点击触发下载。
5. **智能输入**：单框 + 「解析预览」按钮，展示解析出的仓库/URL/账号（账号脱敏 `t***@x`），确认后提交。
6. **鉴权**：顶栏 Token 入口，未配置时全页引导；401 自动弹窗要求重新输入。

## 四、与后端契约的对接清单（前端必读）
- 所有业务端点需 `AUTH_TOKEN`（Bearer）；`/health`、`/ready` 免鉴权。
- 生成红线：`/generate` 带 `execute=true` 返回 **422**，前端应在"生成"与"生成+执行"走不同入口。
- 异步执行一律返回 `task_id`，前端轮询 `/tasks/{id}`，不阻塞。
- 追溯体检以"孤儿数 = 0"为健康标准，前端用红/绿直观提示。
- 报告导出为可选依赖，若后端未装 pdf/docx 库，前端对应菜单项置灰并 tooltip 提示。

## 五、优先级建议
- **演示 MVP（P0 + P1 + P3-2 报告渲染）** 即可覆盖"生成→资产→报告"主链路，对非技术受众已可演示。
- **P2 智能输入 + 生成流水线** 是差异化亮点，建议紧随 MVP。
- **P4 集成/运维** 面向 testhub 远程调用与发布流水线场景，待服务化落地后补。
- 当前 `demo.html` 已覆盖 P0 骨架 + P1 数据视图 + P3 报告/执行记录的**静态原型**，供预览评估布局与交互方向。

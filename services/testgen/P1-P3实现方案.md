# 测试用例生成平台 · P1–P3 实现方案

> 目标：后期**根据本文档逐条实现**。本文给出每个改动的「文件:行号」「具体逻辑」「配置项」「回归测试」「验收口径」。
> 设计基线：沿用已有的 `UI 优先` 机制（`LAYER_STRATEGY=ui_first` + 用例 `coverage_role` 字段），P1/P2/P3 三层产出统一汇入主链路，按 UI 优先排序、接口仅作补充。
>
> **可调项（对应前一轮待确认项，采用推荐默认）**：
> - P1 深度 = **仅排除测试/脚手架**（低风险、零歧义）；调用图吞并列为可选二阶。
> - P2 模型 = **DeepSeek**（base_url=https://api.deepseek.com，model=deepseek-chat）。
> - P3 凭证 = 由用户后续提供测试地址+账号密码，经 `.env` 注入、不入库。

## 0. 总体架构与代码落点地图

主链路（`engine/pipeline.py:run_pipeline` 306–327）：

```
stage_scan         → 扫源码成 SourceFile          (scan.py)
stage_extract      → 提取功能点 FP               (fp_extract.py)
stage_tag          → diff 打标 全量/更新          (diff_tag.py)
stage_test_points  → FP 展开测试点 TP            (tp_expand.py)
stage_enrich       → 规则+LLM 增强 TP            (semantic_enrich.py)  ← P2 接这里
stage_cases        → TP 生成用例 + coverage_role  (case_gen.py)
stage_persist      → 落库（replace + reconcile）   (store.py)
```

三层增强接入点：
- **P1（代码静态·收窄）**：改 `scan.py` + `fp_extract.py` + `config.py`，在 `stage_extract` 之前过滤噪声源。
- **P2（LLM 设计 + PRD 文档）**：改 `semantic_enrich.py` + 新增 `core/doc_ingest.py` + `tp_expand.py` 维度，接 `stage_enrich`。
- **P3（运行时 UI 发现）**：新增 `engine/runtime_ui.py` + `engine/executor.py`，在 `stage_extract` 后插入 `stage_runtime_ui` 合并爬取的 FP。

## 1. P1：收窄「业务函数 → 功能点」提取范围

### 1.1 现状与问题（来自实库统计）
- 全部功能点 1004；其中 `business` 类型 **692（占 69%）**。
- 拆分（启发式归类）：测试/脚手架 ~207、配置/迁移 ~27、真实后端能力 ~438、与 API 同文件辅助 ~54。

**改动 B — 业务函数级文件噪声判定（`engine/fp_extract.py`）**
- 新增常量与判定函数，供 `_extract_api_and_business` 在产出 `BUSINESS` 前过滤：
```python
# fp_extract.py 顶部新增
_BUSINESS_NOISE_DIRS: frozenset[str] = frozenset({"regression", "_fx_test", "scripts", "fixtures"})
_BUSINESS_NOISE_FILE_RE = re.compile(r"(^|/)(test_|selftest_|verify_|conftest)")


def _file_is_business_noise(rel: str) -> bool:
    parts = rel.split("/")
    if any(p in _BUSINESS_NOISE_DIRS for p in parts[:-1]):
        return True
    return bool(_BUSINESS_NOISE_FILE_RE.search(rel))
```
- 在 `_extract_api_and_business`（`fp_extract.py:313` `continue` 之后、业务分支内）加：
```python
# 公开业务函数（无装饰器、非私有、非测试）
if node.name.startswith(_SKIP_FUNC_PREFIXES):
    continue
if _file_is_business_noise(sf.rel):  # ← P1 新增：噪声文件内的函数不产业务 FP
    continue
```

- `fp_extract.extract_functional_points`（`fp_extract.py:384`）新增 `business_extract_mode`、`business_include_dirs` 参数，透传给 `_extract_api_and_business`。

**改动 D（可选二阶，本次不实现，留给调用图吞并）**

## 3. P3：运行时 UI 发现（Playwright 爬真实测试环境）

### 3.1 现状
- `engine/executor.py` **不存在**（Glob 确认）——执行器是全新模块。
- 当前 UI 功能点仅靠静态（`fp_extract._extract_pages/_extract_components/_screen_fp`），看不到：登录后才出现的权限菜单、懒加载模块、真实表单字段/校验。
- 平台执行器当前只做 requests 探活（已知缺口），不跑浏览器。

### 3.2 改动清单

**改动 A — 运行时 UI 爬取（新增 `engine/runtime_ui.py`）**
- 用 Playwright 登录测试环境、遍历路由、收集真实渲染的页面/组件/表单：
  - `async def crawl(base_url, user, password, routes) -> list[FunctionalPoint]`：
    1. `chromium.launch()` + `page.goto(base_url)` → 填登录表单（凭据来自配置）→ 等待 SPA 就绪。
    2. 对每个已知路由（取自静态已提取的 `page` FP 的 `name`/路径，或用户给的路由清单）`goto` 并断言可渲染。
    3. 收集：可见导航项（权限菜单）、`<form>`/`<input>`/`<button>`（交互组件）、懒加载区块。
  - 产出与 `fp_extract` 同结构的 `FunctionalPoint`（`ftype=page/component`），`source` 标注 `runtime:<url>`，`coverage_role` 默认 `primary`（运行时发现优先于静态猜测）。

**改动 B — 执行器基座（新增 `engine/executor.py`）**
- 最小可用：`probe_ui(fp) -> ProbeResult`（Playwright 打开页面，断言可达、关键元素存在）；`probe_api(fp) -> ProbeResult`（requests 探活+静态断言，沿用现状）。为未来自愈/自修复预留接口。

**改动 C — pipeline 接入（`engine/pipeline.py`）**
- `run_pipeline`（306 行）在 `stage_extract` 后插入：
```python
result.functional_points = stage_extract(...)  # 静态
if opts.runtime_ui:  # 新增
    result.functional_points += stage_runtime_ui(opts, result, progress)
```
- 新增 `stage_runtime_ui(opts, result, progress)`：调 `runtime_ui.crawl`，合并 FP，去重（同 `name` 运行时覆盖静态）。
- `PipelineOptions` 新增 `runtime_ui: bool`、`test_env_url/user/password`（从 config 读）。

**改动 D — 配置与凭证（`core/config.py`）**
```python
# P3 运行时 UI 发现
runtime_ui: bool = False
test_env_url: str = ""
test_env_user: str = ""
test_env_password: str = ""  # 仅经 .env 注入，public_dict 不输出
```
- `load_settings` 解析 `RUNTIME_UI`/`TEST_ENV_URL`/`TEST_ENV_USER`/`TEST_ENV_PASSWORD`。
- `public_dict`（`config.py:92`）**绝不**输出 `test_env_password`。

**改动 E — 依赖**
- `pyproject.toml` / 依赖清单新增 `playwright`；安装后执行 `playwright install chromium`。
- **Windows 沙箱风险**：浏览器二进制下载（~150MB）可能受代理/沙箱限制。降级方案：若沙箱不可装，则用「用户给的测试地址做 requests 抓取 HTML + 解析 DOM」替代完整浏览器（仅覆盖服务端渲染页，不覆盖 JS 懒加载）；或在用户本机（非沙箱）运行 P3 阶段。

### 3.3 凭证安全
- `TEST_ENV_PASSWORD` **只从 `.env` 读取**，写 README 明确"禁止 `git add .env`"；`.gitignore` 已排除 `.env`（沿用项目惯例）。
- 爬取凭据不进 `testgen.db`、不进 `public_dict`、不出现在日志明文（日志走 stderr，密码脱敏）。

### 3.4 回归测试与验收口径
- `tests/test_p3_runtime_ui.py`：用 `playwright` 的 `sync`/`async` + 本地 `http.server` 起一个含登录页+受保护页的迷你 SPA fixture，断言 `crawl` 能发现受保护页（静态漏掉的）。
- **验收**：开启 `RUNTIME_UI=on` + 提供测试地址后，UI 层功能点较静态**上升**（补入权限菜单/懒加载/真实表单），且 `coverage_role` 正确标注；接口层不变。

## 4. 实施顺序与里程碑

| 里程碑 | 内容 | 依赖 | 可独立开关 |
|---|---|---|---|
| **M1** | P1 收窄 | 无 | `BUSINESS_EXTRACT_MODE` |
| **M2** | P2 LLM+PRD | 依赖 M1（干净的 FP 集喂 LLM 更准） | `LLM_ENHANCE` / `REVIEW_GATE` |
| **M3** | P3 运行时 UI | 独立（仅需 Playwright 安装 + 用户给地址） | `RUNTIME_UI` |

> 三层均可独立开启/关闭，互不影响；任意一步出问题时改回开关即可回退，**不影响已落库的其他层数据**（replace/reconcile 机制保证重跑干净）。

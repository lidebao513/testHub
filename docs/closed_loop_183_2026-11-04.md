# #183 生成→执行→回流 闭环编排与状态机

日期：2026-11-04　模块：`apps/ui_automation`　关联：`#177` 预探索 / `#181` 三层断言 / `flow.py` 回流

## 1. 背景与目标

平台此前已有四个相对独立的环节：

- **生成**：`testgen_integration` 调 sidecar 生成用例，经 `sync_cases` 幂等回流到 `testcases.TestCase`；用户也可手工建 `ui_automation.AICase`。
- **执行**：`ui_automation` 的 `run_full_process_sync` 用 browser-use 跑 AI 用例，落 `AIExecutionRecord`（status + 断言报告）。
- **断言**：`#181` 三层断言产出 `assertion_report`（quality_signal: pass/warn/fail/none），非阻断落库。
- **回流**：`flow.py` 已有 `sync_cases` / `run_security_verdict` 的注入式编排范式。

缺口：**生成与执行之间没有自动派发，执行结果与断言没有自动回流成「用例当前闭环结论」**，失败用例也没有重试策略。本批把这条链路收口为可观测、可重试的状态机。

## 2. 设计

### 2.1 闭环契约

> **给定一组 `AICase` 作业 → 派发(建 `AIExecutionRecord`) → 执行(`run_full_process_sync`) → 三层断言信号 → 回流写 `AICase.last_loop` + 本轮报告。**

- 生成是**上游生产者**，闭环只**消费** `AICase`（手工或 testgen 衍生均可），不重复造生成轮子（testgen 红线：只生成不执行）。
- 执行落 `AIExecutionRecord`（已天然持久化 status + assertion_report）。
- 回流把「闭环判定」写回 `AICase.last_loop`（JSON，可追溯快照），并产出本轮 JSON/MD 报告到 `data/closed_loop_reports/`。

### 2.2 状态机（`closed_loop.LoopState`）

```
PENDING → DISPATCHED → EXECUTED → ASSERTED → REFLOWED → 终态
终态：DONE(通过) / WARN(告警) / FAILED(失败) / ERROR(基础设施错误) / SKIPPED(用户停止)
回退边：RETRY → DISPATCHED（仅对 ERROR 重试）
```

`can_transition` 校验合法转移；运行时违规仅告警不崩（fail-closed 但健壮）。

### 2.3 闭环核心判定 `combine_verdict(exec_status, assertion_signal)`

| exec_status | assertion_signal | verdict |
| --- | --- | --- |
| passed | pass / none | **pass** |
| passed | warn | **warn** |
| passed | fail | **fail** ← 闭环价值点：执行器自认通过，断言抓到真实问题（空白页/未导航/应显示文案缺失），降级为失败 |
| failed | * | **fail**（以执行器为准） |
| stopped | * | **skipped**（用户被动停止，不计失败） |
| error（异常） | * | **error**（可重试） |

### 2.4 重试策略

仅对 `verdict=error`（基础设施类：超时/网络/鉴权/浏览器崩溃）做有界重试（默认 `max_retries=1`）。
**真实失败 / 告警不重试**——避免对业务缺陷或不确定项无限循环、产生假阳性。

### 2.5 触发方式

`python manage.py run_closed_loop`（fail-open，受 `data/closed_loop.json` 的 `enabled` 门控，默认 false 防误跑）：

- `--case-ids 1,2,3` / `--project-id N`：指定作业来源（CLI 优先于配置）。
- `--dry-run`：不启动浏览器，直接标记 passed + 通过断言，用于验证编排本身与 CI。
- `--max-retries N` / `--force`（忽略 enabled=false）/ `--config` / `--out-dir`。

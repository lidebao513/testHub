## 三、与文档原排序的 5 处差异及理由

### 3.1 新-6 内网拦截：不能照文档「内网段一律拦死」落地（阻塞性冲突）

文档要求：`10.*` / `172.16-31.*` / `192.168.*` / `127.*` / `169.254.*` 默认全部拦截。

**冲突证据**：本平台的核心被测对象就是内网/局域网系统——testhub 自身跑在 `:8900`，aiSitePilot 走局域网 `:8099`，无纸化办公系统在内网。若照文档默认拦死内网段，**平台会把自己的主用例打废**。

**修正方案（建议）**：
- **必拦且不可配置**：`169.254.169.254`（云元数据）及 `169.254.0.0/16` —— 无任何合法测试理由；
- **可配置放行**：`10.*` / `172.16-31.*` / `192.168.*` / `127.*` —— 默认拦截，但命中 `UI_ALLOWED_DOMAINS` 显式白名单即放行（内网测试场景必须显式声明目标，这也是更好的安全姿势）；
- **保留空白名单逃生口**：现有 `check()`（`:372-375`）在 `allowed_domains` 为空时一律放行，注释明确写着「宁可放行」。**不要删除该分支**，否则存量任务会在无配置情况下全线失败。改为：空白名单时仍放行普通域名，但云元数据段照拦。

### 3.2 新-3 模型分级：从「P0 第三位」提到「P0 第二位」

文档把它排在 P0-3，但代码里 `_step_complexity_score` / `_should_redecompose_explicit_steps` 已实现复杂度打分，只需在其上加路由决策。**成本远低于文档预估**，且省下的成本可当场用 `TokenCost` 量化对比，收益最确定。

### 3.3 新-5 会话隔离：从 P1-2 提到 P1 首位

文档排 P1-2，但新-2 三层断言的第三层就是「会话隔离校验」。**隔离不做，断言无处可验**。依赖关系决定它必须先做或同批。

### 3.4 新-2 三层断言：从 P0-2 降到 P1

体量最大（轨迹比对 + 页面终态 + 断言入库 + 截图关联），且依赖新-1（快照）与新-5（隔离）。放 P0 会让首批 PR 面过大、回归成本陡增，与「一批一 PR、可回滚」不符。

### 3.5 #65 从 P1 降到 P3

主体功能（模型配置 CRUD + api_key + 测试连接 + 启停 + 按 role 读取）**均已存在**，不是「新建统一入口」，而是「把已有入口挪到全局配置下 + 补一个 testgen 角色」。继续按 P1 排会重复投入。

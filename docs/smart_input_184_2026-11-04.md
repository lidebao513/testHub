# #184 统一智能输入框 — 设计方案（已确认并实施，2026-11-04）

> 状态：**已实施**。用户确认后按批次 A（后端）→ 批次 B（前端）落地，验收结果见文末附录。
> 依据：`docs/browser_use_enhancement_prompts_2026-11-03.md` 第 9 节（P2-3）+ 2026-11-04 现状勘察。

## 1. 目标（一句话）

用户在 **一个输入框** 里扔一段混合自由文本（"打开 X 页，做 Y，验证 Z"，可混写 URL/账号/密码/权限说明），平台自动解析为结构化任务并落到现有 AI 模式（预探索 + 三层断言 + 模型分级 + 会话隔离）一键执行，**不改动现有结构化配置入口**。

## 2. 现状勘察（2026-11-04）

| 模块 | 现状 | 与 #184 的关系 |
|---|---|---|
| aiSitePilot `src/crawl_input.py` | 纯规则解析混合文本 → `{url, username, password, notes}`（URL 正则 + 账号/密码/权限标签键值对 + 未识别行归 notes） | **直接移植**该解析思路（已验证可用） |
| 前端 `AITesting.vue` | textarea 收 `task_description`（10 行）→「开始执行」调 `run_adhoc`；「存为用例」 | 统一输入框加在此页顶部，解析后可**回填**现有表单 |
| 后端 `views.py::run_adhoc`（:3498） | 只收 `task_description` 一段文本 → 建 `AIExecutionRecord` → 线程异步跑 `run_full_process_sync` | 扩展接收解析结果；解析预览走**新独立端点** |
| AI 基座 | 预探索(#177)、三层断言(#181)、模型分级(#178)、会话隔离(#180)、`ChatOpenAI` 客户端（base_url/key 可配）均已就绪 | #184 只做"入口解析"，不碰执行内核 |

**缺口**：`run_adhoc` 无法结构化理解 URL/凭据/权限；"打开哪页/做什么/验证什么"全靠 LLM 从自由文本里猜。

## 3. 总体设计

```
用户混合文本
   │  ① 解析预览（新端点，纯规则，毫秒级）
   ▼
smart_input.parse_unified_input(text)
   → {url, username, password, notes, actions, asserts, confidence, warnings}
   │  ② 前端展示解析 chips（密码打码），可人工修正
   ▼
   ├─ A. 一键执行：POST run_adhoc（扩展参数）→ 现有 AI 模式异步跑
   └─ B. 拆分回填：写回 AITesting.vue 现有表单，走原结构化路径
```

核心原则：**解析是纯规则、fail-open、零 LLM 依赖**（与 aiSitePilot 同思路）；LLM 增强仅作可选二阶段（本期不做，避免引入不确定性）。

## 4. 解析器设计（`apps/ui_automation/smart_input.py`，纯函数）

### 4.1 输出结构
```python
{
  "url": "http://demo.todomvc.com",        # 第一个 http(s):// 或 域名[:端口]
  "username": "admin",                      # 标签：账号/用户名/username/user/account…
  "password": "Test@123456",                # 标签：密码/口令/password/pwd…（回显时前端打码）
  "notes": ["只读测试，禁止删除数据"],        # 标签：权限/范围/说明/备注… + 未识别非 URL 行
  "actions": ["添加三条任务"],               # 「做」段：动作短句列表
  "asserts": ["剩 0 条 active"],             # 「验证/校验/检查/断言」段文案
  "confidence": "high",                     # high（url+动作齐备）/ low（缺 url 或空 actions）
  "warnings": ["未识别到目标 URL"],           # 人工可读提示
}
```

### 4.2 解析规则（优先级从高到低）
1. **URL**：第一个 `http(s)://` 开头行优先，否则全文正则；纯域名（`demo.x.com[:port]`）兜底。
2. **键值对**：复用 aiSitePilot `KV_RE` 标签集（账号/密码/权限，中英兼容，`[:：=]` 分隔）。
3. **三段语义**（#184 扩展，aiSitePilot 没有）：
   - 「打开/访问/进入 X」→ url（若尚未解析出）
   - 「验证/校验/检查/应显示/断言 Y」→ asserts 列表
   - 其余非 URL 非键值行动作词 → actions 列表
4. **组装任务描述**（供 run_adhoc）：`打开 {url}。{actions…}。验证：{asserts…}。测试账号 {username}（凭据见上下文）。{notes…}` —— 凭据**明文不写入**持久化任务描述（见 §6 安全）。

### 4.3 confidence 与降级
- `url` 与 `actions` 至少其一缺失 → `confidence: low` + warning，前端提示人工修正后再执行（**不阻断**解析预览）。
- 任何解析异常 → 返回原文 `raw` + `confidence: low`，绝不抛错（fail-open）。

## 6. 安全设计（凭据是本特性最大风险点）

1. **不持久化**：密码不写入 `AICase`/`AIExecutionRecord.task_description`/logs；仅在执行线程内注入浏览器上下文。
2. **回显打码**：parse 端点返回 `password_masked`（`Tes******56` 式）供前端展示；明文密码只在前端内存中流转，执行时随请求体送 `run_adhoc`。
3. **存为用例**：若用户点「存为用例」，默认**剔除凭据**（密码置空 + 提示"用例不含凭据，执行时需重新输入"）；可选显式勾选"保存凭据"（后续批次，本期默认不做）。
4. **日志**：后端日志只打 `parse 成功/失败 + confidence`，不打凭据。

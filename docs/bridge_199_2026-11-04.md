# testgen → AICase 自动桥接（#199）

## 背景
#183 闭环已能消费 `AICase` 作业（生成→执行→断言→回流），但 testgen 生成的用例只回流到
`testcases.TestCase`，与 `AICase` 无映射——闭环没有"作业来源"。本任务把 testgen 的 **UI 维度**
用例自动桥接为 `AICase`，打通闭环数据源。

## 关键设计决策（避免 FK 错配）
- `testcases.TestCase.project` 指向通用 `Project`（apps/projects），而 `AICase.project` 指向
  `UiProject`（apps/ui_automation）——**两套不同模型**，testgen 回流拿不到对应的 `UiProject`。
- 因此桥接的 `AICase` **保持 `project=null`**，仅用 `source_ref = tg:<tc_no>` 溯源
  （与 `TestCase` 的 `tg:` 标签同源，便于跨表关联）。
- `AICaseViewSet` 的 queryset 已支持 `project__isnull=True`（`views.py:2928`），桥接项能被列表查出，
  闭环消费只看 `task_description`、不依赖 project，功能闭环完整。

## 改动清单
1. `apps/ui_automation/models.py`：`AICase.source_ref`（CharField, null=True, db_index=True）。
2. `apps/ui_automation/migrations/0008_aicase_source_ref.py`：新增迁移。
3. `apps/testgen_integration/mapping.py`：`case_spec_to_aicase()` —— 结构化用例 → 自然语言浏览器任务
   （步骤渲染文本 + 预期结果；不携带 `project_id`）。
4. `apps/testgen_integration/flow.py`：`bridge_aicases()` —— 与 `sync_cases` 平级的纯函数编排：
   - 过滤：`_is_ui_layer(cs)` 命中才桥接（API/性能用例不进浏览器闭环）；
   - 幂等：`source_ref = tg:<tc_no>` 交给注入式 `bridge` 回调做 `update_or_create`；
   - 返回 `{total, created, updated, skipped}`。
5. `apps/ui_automation/bridge.py`（新增）：`bridge_aicase_real()` —— 真实接线
   （`AICase.objects.update_or_create(source_ref=..., defaults=...)`）。
6. `apps/testgen_integration/views.py`：`TestgenSyncView.post` 在 `sync_cases` 之后调用
   `bridge_aicases`（fail-open：桥接异常仅告警，不阻断主回流），响应合并 `bridge` 计数。

## 验证
- `apps/ui_automation/tests/test_bridge.py`：**6 passed**
  - 离线：过滤非 UI / 幂等不翻倍 / payload 映射（不携带 project_id）/ 预期结果拼接；
  - 真实：`bridge_aicase_real` 建/更幂等，`project is None`；
  - API：`TestgenSyncView` 触发后 UI 用例自动生成 `AICase`（SQLite 不支持 TestCase.tags 的
    JSON `contains`，故集成测试用占位计数替掉 `sync_cases`，聚焦桥接接入；该限制生产 MySQL 无）。
- `pytest apps/ui_automation` 全量：**300 passed**（无回归）。
- `makemigrations --check` 无漂移；新增文件 ruff 全绿。

## 验收
testgen 生成 UI 维度用例 → `/api/testgen/sync` → 自动出现对应 `AICase`（幂等不翻倍、project=null、
source_ref=tg:<tc_no>）→ 可被 #200 闭环触发入口消费。

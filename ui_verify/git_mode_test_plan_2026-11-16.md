# 远程 Git 模式 UI 测试计划（合理性检查 + 代表性用例）

> 角色：测试专家 · 日期：2026-11-16 · 范围：testgen 控制台「远程 Git 模式」操作页
> 原则：先做场景合理性检查；确认合理的场景每个只取少量代表性用例，不穷举。

## 一、系统真实能力边界（合理性检查依据）

通过读后端路由 `apps/testgen_integration/urls.py`、sidecar 实现 `services/testgen/service/repos.py`、新版 UI `services/testgen/service/web/index.html` 实测确认：

| 能力 | 是否提供 | 证据 |
|---|---|---|
| 远程只读列分支 | ✅ | `list_git_branches` 用 `git ls-remote --heads`，不落盘 |
| 远程只读探测仓库 | ✅ | `probe_repo` → `_probe_git`（ls-remote 探活） |
| 远程只读扫描文件 | ✅ | `scan` → `scan_repository`，列模块不克隆 |
| 拉取指定 ref 内容生成用例 | ✅ | `generate` + `branches` + `commits`（只读取内容） |
| 仓库配置增删改查 + 测试连接 | ✅ | `/api/v1/repos` CRUD + `probe` |
| **克隆 / 推送 / 写远端** | ❌ | 系统红线「远程只读取码、不克隆」，无任何写端点 |
| **合并 / 冲突处理** | ❌ | 无 merge/conflict 端点；只读不产生本地 working tree，不存在冲突 |

## 二、场景合理性检查结论

| 用户提出场景 | 系统是否适用 | 判定与替代方案 |
|---|---|---|
| 克隆（clone） | ❌ 不适用 | 设计红线即「不克隆」。**替代**：验证「远程只读扫描 + 只读生成」确实不落盘克隆（正向能力验证）。 |
| 拉取（pull/fetch） | ✅ 适用（语义=只读获取） | 映射为「获取分支」「扫描」「指定 ref 生成」，验证能读到远端内容。 |
| 推送（push） | ❌ 不适用 | 纯只读系统，无写回能力。**排除**，并在报告中说明理由。 |
| 分支切换 | ✅ 适用 | 映射为「选择目标 ref / 基线 ref 下拉」+「获取分支」+「分支阶段对比」。 |
| 冲突处理 | ❌ 不适用 | 无本地 working tree 与 merge，冲突无从产生。**排除**；用「阶段对比」覆盖"差异识别"的等价诉求。 |
| 操作组合 | ✅ 适用 | 如：配置仓库→测试连接→获取分支→扫描→生成→查看报告 的串联。 |
| 异常情况 | ✅ 适用 | 空地址、无效地址、无凭据、离线地址等错误提示。 |

**结论**：原 5 个场景中 2 个适用（拉取、分支切换）、1 个部分适用（操作组合/异常），3 个不适用（克隆、推送、冲突处理——系统只读设计使然）。据理据直接排除不适用场景，不为其编造用例。

## 三、代表性测试用例（每个合理场景少量，不穷举）

### 场景 A：仓库配置管理（正常）
- A1 新建一条远程仓库配置（GitHub SSH 地址）→ 保存成功、出现在列表
- A2 对已存配置点「测试连接」→ 返回成功/分支数

### 场景 B：拉取（只读获取）— 正常
- B1 选远程 Git 模式 + 填有效仓库 → 「获取分支」能列出分支
- B2 选定分支 + 「扫描」→ 列出源模块（不克隆）
- B3 指定 ref 「生成用例」→ 任务提交成功并出报告

### 场景 C：分支切换 — 正常
- C1 切换目标 ref 下拉到另一分支 → 扫描/生成按新分支执行
- C2 选基线 ref → 增量模式识别新增/修改文件

### 场景 D：异常情况（每个代表性 1~2 条）
- D1 空仓库地址 → 明确错误提示（不崩溃）
- D2 无效/不可达仓库地址 → 超时或错误提示，UI 不假死
- D3 远程模式未填凭据（Codeup）→ 提示需要凭据

### 场景 E：操作组合（正常闭环）
- E1 配置仓库 → 测试连接 → 获取分支 → 扫描 → 生成 → 查看进度/报告（一次串联）

> 每条用例执行时截图留证，记录通过/失败与实际现象。
